## 数据来源与局限（面试时要主动说，加分项）

- **来源**：GitHub 公开数据集 `BigCarrey/Data_analysis_in_lagou`（Data_Lagou.xlsx），
  拉勾网"数据分析"类岗位，2016-09 采集，589 条原始数据
- **局限一**：数据是 2016 年的，薪资绝对值只代表当时水平；结论应侧重**结构和相对关系**
  （技能要求排序、城市分布、经验与薪资的关系），这个意识本身就是面试加分项
- **局限二**：技能词频是关键词匹配，"熟悉 SQL"和"精通 SQL"未区分
- **局限三**：交叉分析里"经验 10 年以上 / 1 年以下"分组样本太小，0% 不可信——
  这正是 04_分析.sql 里 `HAVING COUNT(*) >= 10` 存在的意义
- **迭代方向**：用 01 的思路采集 2024+ 新数据，或找更新的公开数据集替换
  `data/raw/` 里的文件 + 改 02 的 `COLUMN_MAP`，主线代码不用动

## 踩坑记录（真实踩过）

1. **小样本陷阱（出现了三次）**：岗位类别里"其他/运营"仅 2 条却以 59.5k 的平均薪资居首；
   查询 6 里宁波 2 条以 50k 排第一；经验"10 年以上"仅 1 条 45k。解法都是 `HAVING COUNT(*) >= 10`
   过滤小样本组，或在报告里明确标注样本量
2. **正则词边界在中文语境失效**：`\bExcel\b` 匹配不到"熟练Excel"——Python 把汉字也算
   单词字符，"练"和"E"之间不存在词边界，导致 Excel 提及率被低估 5 倍（7% vs 38%）。
   解法：`(?<![A-Za-z])技能(?![A-Za-z])` 只按英文字母判边界
3. **口径必须声明**：SQL 的 `LIKE '%SQL%'` 会把 "MySQL" 也计入（44%），独立提及口径是 40%。
   两个数都对、口径不同；任何对外引用的数字都要能说清"怎么算的"
4. **读数要读源头**：项目过程中曾因看截图读错数字得出错误结论（"数据工程是数据分析 2.2 倍"，
   实际 1.35 倍），最终以直接对数据重算为准——永远别相信二手转述，包括自己的眼睛
